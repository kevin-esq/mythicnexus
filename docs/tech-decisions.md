# Technical decisions

| Area                | Choice                                         | Notes                                                                                                                                                                                                             |
| ------------------- | ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Monorepo            | pnpm workspaces + Turborepo                    | Single lockfile; cacheable `build` / `dev` tasks                                                                                                                                                                  |
| Frontend            | Next.js (App Router), TypeScript, Tailwind CSS | UI components can adopt shadcn/ui incrementally                                                                                                                                                                   |
| Data fetching       | TanStack Query                                 | Client cache and server-state patterns for API calls                                                                                                                                                              |
| Backend             | ASP.NET Core 9, minimal APIs                   | Modular registration per bounded context under `src/Modules`                                                                                                                                                      |
| Persistence         | EF Core 9 + Npgsql                             | PostgreSQL only; no SQLite                                                                                                                                                                                        |
| Validation          | FluentValidation                               | Request validators as features grow                                                                                                                                                                               |
| Local orchestration | **One** `docker-compose.yml` at repo root      | Postgres (and future shared deps like Redis) in one place; `docker compose up -d postgres`. Avoid per-app compose unless an app is developed/deployed as an isolated stack.                                       |
| Local DB            | Docker Compose, `postgres:16`                  | Default dev connection lives in `appsettings.Development.json`; override with `apps/api/.env` or `ConnectionStrings__Default`. Remote Supabase uses the same API/EF code path with a different connection string. |
| Local configuration | Next: `.env.local`; API: `.env` + JSON         | Next reads `.env*` natively; API loads optional `apps/api/.env` before host startup via `DotNetEnv` (see `LocalEnvLoader`)                                                                                        |

Open items: authentication mechanism (cookies vs JWT), CI workflow shape, hosting targets.
